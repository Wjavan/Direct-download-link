# 探究：如何提高各大网盘的下载速度

## 背景

GreasyFork 用户反馈（[discussion 341075](https://greasyfork.org/zh-CN/scripts/595544-ferrylink/discussions/341075)）：

> 2，迅雷网盘下载速度比之前慢很多且不稳定，平均约100-120kb左右，时间长了速度会降至50k/s，原本能一直稳定到250kb/s左右，试了很多文件都是如此，是网盘服务器端原因或者账号风控尚未知

同用户之前可以稳定 250KB/s，现在平均 100-120KB/s、长时间降到 50KB/s。多文件复现。

维护者自己的实测（2026-10-04）：

- 迅雷 5.7GB 文件：浏览器下载和 IDM 都不到 10KB/s，且都是单线程
- 迅雷 8.5MB 文件：约 130KB/s
- 百度 OAuth 通道：约 200KB/s（官方未公布固定限速值，可能与会员/节点/通道有关）

## 已知事实

1. **浏览器和 IDM 速度一样** → 不是脚本链路问题（拿链接 → 传 Cookie → 交给下载方，两条路径走的是同一个 URL、被服务端同样对待）
2. **小文件快、大文件慢** → 符合「小流量放行、大流量限速」的服务端策略；8.5MB 在限速生效前就下完了
3. **迅雷 CDN 需要认证**：`__pus` / `__puus` cookie（aria2 导出和 IDM 推送都已带）
4. **迅雷 mirror 列表有 100+ 节点**（`vod0007-h05-vip-lixian.xunlei.com` 等），服务端选哪个不可控
5. **IDM 退化成单线程**最常见的原因是服务器拒绝 Range 分段请求（响应头没有 `Accept-Ranges`），或链接级限速 `ms=153600` 配额生效

## 待探究的问题

### 1. 迅雷多连接能否绕过限速？

- IDM 32 线程实际只开 1 条（5.7GB 文件实测），是服务器拒绝 Range 还是被限速到单连接？
- 用 aria2（16 连接，脚本已带 cookie）跑同一 5.7GB 文件：
  - 快 → 服务器支持 Range，IDM 侧问题，可考虑调整脚本给 IDM 传递的参数
  - 慢 → 服务端限速，代码无解

### 2. 官方迅雷客户端对照

- 客户端下载同一 5.7GB 文件快 → 迅雷故意把 API/直链流量限速，逼用客户端
- 客户端也慢 → 账号本身被风控/限速

### 3. mirror 节点是否影响速度？

- 5.7GB 和 8.5MB 两个文件命中的 mirror 节点是否相同？（链接 host 可以直接看）
- 不同节点手动测试（改链接 host，其他参数不动），速度是否有差异？

### 4. 百度 OAuth 通道是否可换？

- 百度 PCS 有多个域名（`d.pcs.baidu.com` / `cts*.pcs.baidu.com` / `w*.pcs.baidu.com`），不同域名限速是否不同？
- 会员账号和免费账号在同一通道上的速度差异（用于确认是否「与会员无关」——目前没有证据下这个结论）

### 5. 时间相关性（用户反馈「时间长了会降」）

- 是单文件下载时间长后被限速，还是累计流量到阈值后被限速？
- 中断重连（IDM 暂停/继续）是否恢复速度？

## 排除项

- 脚本本身的链路（链接获取、Cookie 传递、下载方推送）已验证正确
- 不编造「固定限速 XX KB/s 与会员无关」这类未经证实的结论

## 需要的信息

- 有会员/非会员迅雷账号的用户分别测速的结果
- aria2 跑 5.7GB 文件的速度（脚本 Aria 模式复制命令即可）
- 官方客户端对照
